# Engine API: connecting the front end

Everything the studio needs from the engine is behind one typed client,
`src/engine/client.ts`. The full capability catalogue, with every parameter,
is in [ENGINE_CAPABILITIES.md](ENGINE_CAPABILITIES.md). Both are generated
from, or checked against, the engine itself.

```
panel ──engine.run(…)──▶ /api/engine/* (server.ts: adds ENGINE_TOKEN, X-Engine-User)
                                   ──▶ <engine>/v2/* (Cloud Run)
```

## How it stays connected

| Piece | Where | Kept in step by |
|---|---|---|
| Parameter types for all 63 capabilities, the catalogue, and the route list | `src/engine/contract.generated.ts` | Generated by `python mlops_service/scripts/gen_contract.py`. `tests/test_v2_contract.py` fails if it's out of date. |
| One client method per engine route | `src/engine/client.ts` (`CLIENT_ROUTES`) | `client.test.ts` fails if an engine route has no method, or a method has no route. |
| Proxy and token | `server.ts` (`/api/engine/*`) | Every request gets `X-Engine-Token`. JSON answers are re-sent as JSON, so they work with the background-job layer. |

**After changing the engine:** run the generator and commit the generated file
together with the engine change.

## Using it

```ts
import { engine, EngineApiError } from '../engine/client';

const ds = await engine.datasets.upload(file, 'Sales');               // ≤ ~30 MB
// const ds = await engine.datasets.uploadLarge(file, 'Sales');        // bigger: straight to Cloud Storage

const result = await engine.runAndWait('ts.forecast', { date: 'month', value: 'sales', horizon: 12 }, {
  datasetId: ds.id,
  experiment: 'Q3 plan',                                   // groups runs for comparison
  onProgress: (p, message) => setProgress(p, message),     // shown while a job runs
});
result.manifest;  // engine/library versions, data fingerprint, params, seed: show it as provenance
result.runId;     // for engine.runs.methods(runId) and engine.runs.notebookUrl(runId)
```

Parameters are type-checked per capability. `engine.run('stats.compare', { column: 'x' })`
is a compile error, because `stats.compare` takes `a` and `b`.

### Sync or job?

`runAndWait` defaults to `mode: 'sync'`. The request stays open on the engine,
which Cloud Run needs in order to give the work CPU. In the browser, the call
goes through `apiFetch`: the studio server answers at once, and the browser
polls. This survives Safari's 60-second limit, and the work appears in the
jobs panel, labelled with the capability's title.

`mode: 'job'` returns at once with a job id that `runAndWait` follows. Use it
when the engine runs with `--no-cpu-throttling`, or locally.

### Errors

Every failure is an `EngineApiError` with `status`, `code` and a message that
can be shown to the user.

| Status | Codes | Meaning |
|---|---|---|
| 400 | `bad_request`, `not_supported` | The data or parameters can't be used. The message says why. |
| 401 | `unauthorized` | Token missing or wrong (a server configuration problem). |
| 403 | `approval_required` | Promoting a model to production needs an approver. |
| 404 | `not_found` | Unknown dataset, model, run, job or schedule. |
| 409 | `in_production` | Archive the production model before deleting it. |
| 413 | `too_large` | The upload is over the size limit. |
| 422 | `invalid_params`, `missing_features`, `too_many_rows` | Parameter validation failed. The message names the field. |
| 503 | `model_unavailable`, or a proxy error | The engine (or a text model) isn't reachable. |

## The surface, by panel

| Panel | Calls |
|---|---|
| Datasets and connectors | `datasets.upload` / `uploadLarge` / `fromRows` / `list` / `get` / `preview` / `query` (read-only SQL over `data`) / `remove`; `run('connect.url' \| 'connect.gcs' \| 'connect.bigquery' \| 'connect.sql')` |
| Profiling and quality | `data.profile`, `data.validate`, `data.outliers`, `data.pii_scan`, `data.pii_mask`, `data.estimate` |
| Preparation | `data.recipe` (`preview: true` while editing, then save) |
| Statistics | `stats.*`, `bayes.*`, `survival.*` |
| Causal and experiments | `causal.*`, `exp.*` |
| AutoML and explanations | `ml.automl` (`text_encoder: 'minilm-en'` for text features), `ml.explain`, `ml.fairness`, `ml.feature_selection`, `ml.predict` (batch) |
| Forecasting | `ts.forecast`, `ts.decompose`, `ts.anomalies`, `ts.changepoints`, `ts.hierarchical` |
| Segments | `unsup.cluster`, `unsup.embed`, `unsup.association_rules` |
| Text | `text.sentiment`, `text.zero_shot`, `text.entities`, `text.semantic_search`, `text.semantic_topics`, `text.embed` (transformers); `text.analyze`, `text.similarity` (classical); `textModels()` for which models are installed and their licences |
| Optimisation | `opt.monte_carlo`, `opt.linear_program`, `opt.scenarios` |
| Model registry | `models.list` / `get(ref)` / `update` (stage, name, description, approval) / `card` / `downloadUrl` / `remove`. A `ref` is an id or `name`, `name@production`, `name@staging`, `name@latest` or `name@v3`. |
| Serving | `models.predict(ref, rows, { explain: true })`: predictions, probabilities, conformal sets or intervals, and reasons |
| Monitoring | `run('mlops.monitor', { model: ref, target? })` on new data, or with `source: 'prediction_log'`; `models.monitoring(ref)` for history |
| Experiments and reports | `runs.list({ experiment })`, `runs.get`, `runs.compare(ids)`, `experiments()`, `runs.methods(id)`, `runs.notebookUrl(id)` |
| Automation | `pipelines.run({ steps })` (pass `$prev` to hand a dataset or model on), `schedules.*` |
| Admin | `info()`, `capabilities()`, `audit()` |

## Result shapes

Every capability result has its own fields plus `manifest`, and `notes` when
the engine wants to say something, such as sampling or dropped rows. Fields
the panels will commonly use:

- **Any result that saved data:** `dataset` (a `DatasetMeta`, ready for preview or the next step).
- **A result that trained a model:** `model: { id, name, version }`.
- **Charts:** arrays of plain points, such as
  - `forecast: [{ date, value, lower, upper }]`
  - `roc: [{ fpr, tpr }]`
  - `map: [{ x, y, … }]`
  - `histogram`
  - `components`

Charts never need recomputing in the browser. The exact fields per capability
are in its code under `mlops_service/engine/capabilities/`, and in the
engine's tests, which assert on them.
